# 2D 비휴머노이드 움직이기, 기성품 대신 직접 만든다

결론부터 말하면 **우리 조건을 모두 만족하는 2D 기성 해법은 없다.** 조건은 아이 그림 사진 한 장, 사람 손 없이 자동, 아이 그림 모습 그대로 2D, 상업 이용 가능, 싸고 수십 초 안이다. 상용 시장은 세 갈래로 나뉜다. 사람 모양만 자동으로 움직이는 Meta AnimatedDrawings, 무엇이든 움직이지만 그림을 새로 그려 버리는 생성 영상 앱, 그리고 미리 인쇄한 도안에 색칠하게 하는 teamLab·Quiver 방식이다. "자유롭게 그린 그림 + 비휴머노이드 + 그림 픽셀 그대로 + 자동"이라는 가운데 칸은 비어 있다. 전문 도구인 **Live2D Cubism과 Moho Pro는 둘 다 사람이 부위를 나누고 뼈를 심어야 하는 저작 도구라 우리 파이프라인에는 맞지 않는다.** Live2D의 자동 기능은 사람 몸 전용이고, SDK 라이선스도 우리 구조에서는 소규모 면제를 받기 어렵다. 연구 쪽도 사정이 같다. 2D·자동·비휴머노이드·상업 라이선스를 한꺼번에 갖춘 공개 연구는 없었다. 대신 바로 가져다 쓸 수 있는 부품(뼈대 가지치기, 경계 구속 메시, 브라우저 메시 재생, 자동 가중치, 아이 그림 부위 데이터셋)은 충분히 있다. 그래서 1순위는 지금 만들고 있는 "모양 뼈대 + ARAP 변형" 노선을 이 부품들로 다듬는 것이다. 팀이 검토 중인 "단계별 움직임 + 자신 없을 때만 보호자가 종류 카드 고르기(S-06 확장)" 방향도 이번 조사 결과와 잘 맞는다.

## 상용 시장 세 갈래, 가운데 칸이 비어 있다

아이 그림을 움직여 준다는 소비자 앱은 많다. DrawToLife, Drawings Alive, Drawmingo, KidsAI, Animate my Drawing, Pixley 같은 앱이 "동물도 된다"고 내세운다. 하지만 이 앱들은 사실상 모두 **이미지를 영상으로 바꾸는 생성 모델 위에 화면만 얹은 형태**다. 경쟁사가 쓴 비교표도 DrawToLife를 "Generative AI video", AnimatedDrawings를 "Skeleton rigging / Figures only"로 분류한다 ([draw-to-life.com 블로그](https://draw-to-life.com/blog/best-apps-bring-kids-drawings-to-life/)). Drawings Alive는 사용자가 짧은 설명 문장을 넣어 생성을 이끄는 방식이다 ([G2](https://ai.g2.com/marketplace/tools/drawings-alive)). KidsAI는 "선은 아이 것 그대로, 렌더링만 AI가 더한다"고 홍보하지만 6~10초 영상을 크레딧으로 판다 ([kidsai.art](https://kidsai.art/)). Drawmingo는 영상 하나에 **2~5분**이 걸리고 768p MP4로 나온다 ([drawmingo.com](https://drawmingo.com/)). 이 앱들은 모두 API를 공개하지 않는다. 아이 그림 전용 B2B API를 파는 회사도 찾지 못했다 ([draw-to-life.com 블로그](https://draw-to-life.com/blog/best-apps-bring-kids-drawings-to-life/)). 한국어·중국어로 찾아봐도 국내외 전용 서비스는 나오지 않았다.

그림 픽셀을 그대로 두고 메시를 변형하는 "리깅형" 자동 제품은 AnimatedDrawings 하나뿐이다. 이것도 사람 모양만 받는다 ([About Meta](https://about.fb.com/news/2021/12/using-ai-to-animate-childrens-drawings/)). 비휴머노이드를 안정적으로 움직이는 가장 오래된 상용 해법은 도안 방식이다. teamLab Sketch Aquarium은 "나눠 준 종이의 물고기에 색칠"하게 한다 ([teamLab](https://teamlab.art/w/aquarium/milanosalone2014)). Quiver는 350개가 넘는 인쇄 도안을 미리 만든 3D 모델에 입힌다 ([quivervision.com](https://quivervision.com/)). 미리 리그를 만들어 두니 늘 성공하지만, "아이가 자유롭게 그린 그림"이라는 우리 서비스 취지와는 정면으로 부딪친다. 결국 **확인한 상용 제품 가운데 비휴머노이드 그림의 다리·꼬리·날개를 스스로 찾아 2D 리그를 만드는 것은 하나도 없다.**

비휴머노이드를 다루는 다른 상용 갈래도 우리 조건에서 벗어난다. Krikey는 동물·사물을 자사 **3D** 캐릭터 라이브러리로 바꿔 끼운다 ([Krikey](https://www.krikey.ai/learn/how-to-create-animated-characters)). Viggle은 공개 API가 있고 1크레딧이 $0.01로 싸다. 하지만 사람 동작 영상으로 그림을 휘게 하는 방식이고, API 예시도 사람 캐릭터뿐이다. 동물·괴물을 받아 주는지는 문서에 없다 ([Viggle developers](https://viggle.ai/developers)).

### Live2D Cubism과 Moho Pro는 "사람이 만드는" 도구다

사용자가 따로 물은 두 도구부터 분명히 해 둔다. **Live2D Cubism은 부적합하다.** 이유는 세 가지다. 첫째, 5.1에 들어간 AI "자동 디포머 생성"은 **사람(휴머노이드) 전신 모델 전용**이다. 게다가 부위별로 나눈 PSD를 가져온 직후에만 동작하고, "자동 흔들림 생성"도 머리카락·장신구용이다 ([Live2D 5.1 New Features](https://docs.live2d.com/en/cubism-editor-manual/new-function5-1/)). 아이 그림 사진 한 장에는 부위별 레이어가 없으니 첫 단계부터 사람 손이 필요하다. 둘째, AI 기능은 월 ¥2,280부터인 PRO 버전 데스크톱 에디터 안에 있다. 서버에서 부를 수 있는 기능이 아니다 ([AUTOMATON](https://automaton-media.com/articles/newsjp/20240730-303793/)). 셋째, SDK 라이선스가 걸린다. 개인·소규모 사업자(연 매출 1,000만 엔 미만)는 출시 계약이 면제된다. 그러나 "최종 사용자가 Live2D 모델을 들여오거나 만드는 도구", 즉 Expandable Application은 소규모 사업자도 사전 심사와 특별 계약을 거쳐야 한다 ([Live2D SDK license](https://www.live2d.com/en/?p=586)). 아이 그림마다 모델을 새로 만드는 우리 서비스는 이 분류에 들 가능성이 크다. 정확한 해당 여부는 Live2D에 문의해야 알 수 있다.

**Moho Pro도 부적합하다.** Moho의 대표 기능인 Smart Bones는 사람이 뼈를 골라 액션을 만들어 두면 변형이 따라오는 방식이다. 처음 뼈를 심고 액션을 짜는 일은 모두 사람이 한다 ([Moho features](https://moho.lostmarble.com/pages/features)). 그림 한 장에서 뼈대를 자동으로 만들어 주는 기능이나 서버 자동화 API는 이번 조사에서 찾지 못했다. 같은 부류인 Reallusion Cartoon Animator 5에는 개·고양이·말 같은 네발 동작 라이브러리와 PSD 템플릿이 있다. 하지만 템플릿을 쓰려면 부위별 레이어를 사람이 만들어야 한다. "AI가 동물을 알아보고 뼈를 붙여 주는 기능"은 사용자 요청 게시판에 올라온 **요청일 뿐 구현되지 않았다** ([Reallusion Feedback Tracker](https://www.reallusion.com/FeedBackTracker/Issue/AI-Integration-Ideas-and-requests)). Rive는 런타임이 MIT지만 뼈·메시·자동 가중치가 모두 에디터 안의 작업이다 ([Rive Bones](https://rive.app/docs/editor/manipulating-shapes/bones)). Adobe Character Animator도 사람이 부위에 태그를 단다 ([Toolfarm](https://www.toolfarm.com/?p=17984)). Toon Boom Harmony 25의 AI 기능은 업스케일·이미지 확장 같은 작업 보조에 그친다 ([Toon Boom docs](https://docs.toonboom.com/help/harmony-25/premium/ai/ai-features.html)). 이 도구들에서 참고할 만한 것은 "네발 동작 라이브러리"라는 발상 정도다. 우리는 이미 CMU mocap 걸음 곡선으로 그 일을 하고 있다.

## 연구는 완제품 대신 부품과 데이터를 준다

2023~2026년 연구를 넓게 훑어봐도 **"사진 한 장 → 완전 자동 → 2D 그림체 유지 → 비휴머노이드 → 상업 라이선스"를 모두 갖춘 공개 연구는 없었다.** 2025년 스케치 애니메이션 종합 보고서도 AnimatedDrawings를 두고 "두 발 동작이라 사람 아닌 캐릭터로 일반화가 어렵다"고 평가한다. 사람 신체 모델(SMPL)에 기대는 방법들은 임의 형태에 약하다는 점도 열린 과제로 꼽는다 ([Sketch Animation STAR](https://arxiv.org/html/2510.10218)). 네발·무생물까지 실시간으로 보여 준 SketchAnim은 아이디어를 참고할 가치가 크다. 다만 구동 영상이 필요하고 웹페이지 라이선스가 비상업(CC BY-NC-SA)이다 ([SketchAnim](https://graphics-research-group.github.io/SketchAnim/)). Monster Mash는 Apache-2.0이지만 사용자가 직접 조작해야 하고, 빌드에 상업 금지 조항이 있는 Triangle 라이브러리가 들어간다 ([google/monster-mash](https://github.com/google/monster-mash)). DrawingSpinUp, Puppet-Master, DragAPart는 저장소에 **LICENSE가 없다.** 라이선스가 없으면 모든 권리가 저작권자에게 있으므로 상업 이용은 안 된다고 봐야 한다 ([DrawingSpinUp](https://github.com/LordLiang/DrawingSpinUp), [Puppet-Master](https://github.com/RuiningLi/puppet-master)). UniRig·Make-It-Animatable·RigAnything은 자동 리깅이지만 입력이 **3D 메시**다 ([Make-It-Animatable](https://github.com/jasongzy/Make-It-Animatable), [RigAnything](https://arxiv.org/html/2502.09615v1)).

그래도 쓸모 있는 재료는 나왔다. 가장 가치 있는 것은 Meta의 **ChildlikeSHAPES 데이터셋**이다. 아이 그림 16,075장에 25개 부위의 픽셀 단위 라벨을 단 데이터이고 **CC-BY 4.0이라 출처만 밝히면 상업용 모델 학습에 쓸 수 있다** ([AnimatedDrawings README](https://github.com/facebookresearch/AnimatedDrawings#childlikeshapes)). 논문은 이 데이터로 학습한 SAM 기반 분할기가 "적은 재학습으로 만화 동물에 적응한다"고 보고했다 ([arXiv 2504.08022](https://arxiv.org/html/2504.08022v1)). 다만 분할 모델 가중치가 공개됐는지는 확인되지 않았다. 25개 부위도 "몸과 얼굴" 기준이라 꼬리·날개 라벨은 없을 것으로 보인다. 원천인 Amateur Drawings(17.8만 장, MIT)의 마스크는 동물 그림의 배경 분리에도 통한다 ([arXiv 2303.12741](https://arxiv.org/abs/2303.12741)).

부위를 자동으로 찾는 모델들은 조건이 붙는다. PoseAnything·CapeX 같은 범주 무관 키포인트 모델은 Apache-2.0이다. 하지만 **"기준 그림 한 장 + 그 위의 점"이나 점에 대한 글 설명**이 있어야 하고, 사진으로만 학습돼 아이 낙서에서는 검증된 적이 없다 ([PoseAnything](https://github.com/orhir/PoseAnything), [CapeX](https://github.com/matanr/capex)). 기준 그림 없이 되는 X-Pose는 학습 데이터가 비상업 전용이라 뺀다 ([X-Pose](https://github.com/IDEA-Research/X-Pose)). SAM 3는 짧은 글("tail")로 분할하고 상업 이용도 허용한다. 그러나 848M 파라미터에 CUDA GPU가 필요하다 ([sam3](https://github.com/facebookresearch/sam3)). 이미지 언어 모델에게 좌표를 직접 찍게 하는 방법은 연구계가 "객체 수준에 머물고 부위 수준·픽셀 정밀 포인팅은 약하다"고 보고한다 ([Talking Points](https://arxiv.org/html/2510.14583v1)). 그러니 모양 뼈대로 후보 점을 만들고, 모델에게는 "이 번호 점이 머리인가 꼬리인가"만 묻는 방식이 더 안정적일 것이다. 이는 `experiments/joint-labeling/`의 방향과 같다.

동작 쪽에서는 아무 골격에나 움직임을 만들어 주는 AnyTop(코드 MIT, 이족·네발·비행·뱀 모델 제공)이 눈에 띈다. 그런데 학습 데이터가 유료 상품인 Truebones Zoo이고, 저자도 "라이선스 확인 중"이라며 가공 데이터 배포를 멈췄다 ([AnyTop](https://raw.githubusercontent.com/Anytop2025/Anytop/main/README.md)). 글로 동작을 요청할 수 있는 UniMate(SIGGRAPH Asia 2026)는 새·곤충·뱀까지 일반화한다고 하지만 아직 다 공개되지 않았다 ([arXiv 2609.05415](https://arxiv.org/html/2609.05415)). 당장은 CMU mocap 재사용과 절차적 걸음이 더 안전하다.

## 생성 영상은 싸고 빠르지만 그림을 바꾸고, 약관이 아이를 막는다

생성 영상의 장점은 분명하다. 무엇이든 움직이고, 값이 내려갔고, 빠르다. 2026년 10월 기준 초당 가격은 MiniMax H3 Max Turbo의 **$0.015**부터 Kling v3 Pro의 $0.14까지 다양하다 ([fal pricing](https://fal.ai/pricing)). Runway gen4_turbo는 $0.05다 ([Runway API pricing](https://docs.dev.runwayml.com/guides/pricing/)). 응답 시간은 집계 사이트 기준 15~60초다 ([magichour leaderboard](https://magichour.ai/model-leaderboard/image-to-video)). 클립 4~8개에 재시도를 1.5배로 잡으면 이야기 한 편에 최저가 모델은 약 $0.3~1, 중간 모델은 $1~6이 든다. 이것은 위 단가로 한 단순 계산이다.

하지만 우리에게 걸리는 문제가 두 가지 있다. 첫째, **그림이 바뀐다.** Meta 연구진은 "아이 그림은 학습 데이터에 극히 드물어 생성 모델이 잘 움직이리라 기대하는 것은 무리"라고 썼다. 움직임 제어와 캐릭터 정체성 유지도 "아직 풀리지 않은 과제"라고 보고, 리깅 쪽(2.5D)을 택했다 ([arXiv 2502.17866](https://arxiv.org/html/2502.17866v1)). 실무 가이드도 명암과 질감이 많은 입력은 2~3초 무렵부터 실사 쪽으로 번진다고 말한다 ([invideo FAQ](https://invideo.io/faq/how-do-you-stop-ai-from-drifting-into-photorealism-when/)). 다리 없는 괴물에 다리가 생기거나, 삐뚤한 비율이 "바르게" 고쳐지는 일은 아이가 "내 그림이 아니다"라고 느끼게 만드는 실패다.

둘째, **가격보다 약관이 먼저 막는다.** Gemini API(Veo·Omni)는 "18세 미만이 대상이거나 접속할 가능성이 큰 서비스"에서 쓰는 것을 금지한다 ([Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)). Runway는 아동 대상 시각 스타일을 가진 캐릭터를 금지하는 조항이 있다 ([Runway usage policy](https://runway.com/safety/usage-policy)). Kling은 업로드한 콘텐츠를 연구·개선에 쓸 권리를 둔다 ([Kling user policy](https://kling.ai/docs/user-policy)). Sora 2 API는 2026-09-24에 종료됐다 ([OpenAI](https://developers.openai.com/api/docs/models/sora-2)). 오픈 모델로 가면 아이 데이터를 밖으로 보내지 않아도 된다. Wan 2.2는 Apache 2.0이다. 대신 24GB GPU에서 5초 720p 한 편에 **9분 가까이** 걸린다 ([Wan2.2](https://github.com/Wan-Video/Wan2.2)). HunyuanVideo-I2V는 적용 지역에서 **대한민국을 명시적으로 뺐다** ([HunyuanVideo-I2V LICENSE](https://huggingface.co/tencent/HunyuanVideo-I2V/blob/main/LICENSE)). AnimateAnyone·Animate-X 같은 포즈 기반 모델은 사람 춤 영상으로 움직이니, 네발·뱀에는 넣을 신호가 없다 ([Animate-X](https://arxiv.org/html/2410.10306v2)). LivePortrait는 얼굴만 움직인다 ([LivePortrait](https://github.com/KlingTeam/LivePortrait)).

반대 의견도 공정하게 짚어 둔다. 생성 영상은 "몸통만 흔들기"보다 훨씬 이야기다운 움직임을 줄 수 있고, 시장의 소비자 앱 대부분이 이 길을 택했다. 다만 우리 서비스의 약속은 "내 그림이 움직인다"이다. 그래서 생성 영상은 주 경로가 될 수 없다. 나중에 쓴다면 배경 연출이나 시험용 비교군 정도가 맞다.

## 조건별 순위: 자체 리깅이 유일하게 모든 칸을 채운다

아래 표는 우리 조건에 맞춰 후보를 한 줄로 세운 것이다. "그대로"는 아이 그림 픽셀이 그대로 남는지, "안전"은 아이 데이터가 밖으로 나가지 않거나 약관이 허용하는지를 뜻한다.

| 순위 | 후보 | 비휴머노이드 | 자동 | 그대로 | 상업 라이선스 | 비용·속도 | 안전 | 판정 |
|---|---|---|---|---|---|---|---|---|
| 1 | 자체 리깅(모양 뼈대 + ARAP + 단계별) + 아래 오픈소스 부품 | 단계별로 항상 뭔가 됨 | 됨(애매하면 S-06) | 됨 | 부품 모두 MIT·BSD·MPL·Apache | 서버 CPU, 호출당 과금 없음 | 내부 처리 | **채택** |

| 3 | 도안 방식(teamLab·Quiver식) | 도안 종류만 | 됨 | 색만 | 자체 제작 | 쌈 | 내부 처리 | 자유 그림 취지와 충돌, 보조 아이디어로만 |

1위가 1위인 이유는 기능이 가장 좋아서가 아니다. **여덟 칸 가운데 하나라도 막히지 않는 후보가 이것뿐이어서다.** 오픈소스 조사도 같은 결론에 닿았다. 2026년 10월 기준으로도 AnimatedDrawings(2025-09 보관 처리)가 사실상 유일하게 성숙한 오픈소스였다. "doodle animation rig"로 GitHub를 검색하면 결과가 0건이다 ([AnimatedDrawings](https://github.com/facebookresearch/AnimatedDrawings), [GitHub 검색](https://github.com/search?q=doodle+animation+rig&type=repositories)). 비휴머노이드 자동화는 우리가 만든 쪽이 앞서 있다는 뜻이다. 다만 새와 곤충은 따로 짚어야 한다. 2D 그림에서 날개나 여러 다리를 자동으로 찾는 공개 해법은 이번 조사에서 하나도 나오지 않았다. 지금 쪽으로는 "가지 끝 찾기 + 날갯짓·다리 흔들기 규칙"을 직접 시험해야 하는 미검증 영역이다.

## 우리 파이프라인에 바로 넣을 부품과 피할 것

지금 `shape_rig.py`는 `cv2`, `scipy.spatial.Delaunay`, `skimage.morphology.skeletonize`, 자체 `arap2d.ARAP2D`만 쓴다. 라이선스 위험이 있는 의존성은 없다. 아래 부품은 이 깨끗한 상태를 지키면서 약점을 메운다.

| 부품 | 하는 일 | 라이선스 | 넣을 자리 |
|---|---|---|---|
| skan `Skeleton`·`summarize`·`prune_paths` ([jni/skan](https://github.com/jni/skan)) | 뼈대를 그래프로 바꾸고 짧은 잔가지 쳐내기 | BSD-3 | `shape_rig.py` 뼈대 단계 |
| DSE 가지치기 ([originlake/DSE-skeleton-pruning](https://github.com/originlake/DSE-skeleton-pruning)) | 모양 기여도로 잔가지 제거, 굵기 변화에 강함 | MIT | skan 대안 |
| sknw ([Image-Py/sknw](https://github.com/Image-Py/sknw)) | 뼈대 → networkx 그래프 | BSD-3 | 가지·마디 분석 |
| PythonCDT ([artem-ogre/PythonCDT](https://github.com/artem-ogre/PythonCDT)) | 외곽선을 지키는 메시, 다리 사이가 붙지 않게 | MPL-2.0 | 메시 단계(다리가 붙어 움직일 때) |
| PixiJS v8 `MeshSimple`·`MeshRope` ([Pixi Mesh 가이드](https://pixijs.com/8.x/guides/components/scene-objects/mesh)) | 브라우저에서 아이 그림 텍스처를 메시로 재생, Rope는 "뱀" 용도로 문서에 명시 | MIT | 프론트 재생 |
| libigl 파이썬 `bbw` ([libigl-python-bindings](https://github.com/libigl/libigl-python-bindings)) | 뼈마디별 자동 가중치 → 브라우저 GPU 스키닝 | 코어 MPL-2.0 | 실험(아래 주의 참고) |
| MLS 변형 ([Jarvis73/Moving-Least-Squares](https://github.com/Jarvis73/Moving-Least-Squares)) | 뼈대 없이 제어점 몇 개로 변형 | MIT | 몸통만 단계(별·구름) |
| shape matching ([Müller 2005](https://cg.informatik.uni-freiburg.de/publications/2005_SIGGRAPH_deformationShapeMatching.pdf)) | 말랑한 2차 움직임, 늘 안정 | 논문, 직접 구현 | 몸통만 단계의 젤리 느낌 |
| ChildlikeSHAPES ([README](https://github.com/facebookresearch/AnimatedDrawings#childlikeshapes)) | 아이 그림 25개 부위 라벨 | CC-BY 4.0 | 부위 분할기 학습 재료 |
| SAM 2 ([sam2](https://github.com/facebookresearch/sam2)) | 분할 기반 모델 | Apache-2.0 | 부위 분할기 바탕 |
| PoseAnything·CapeX ([PoseAnything](https://github.com/orhir/PoseAnything)) | 종류별 기준 그림 한 장으로 점 찾기 | Apache-2.0 | 종류 카드별 미리 놓을 점 후보(미검증) |

libigl에는 주의할 점이 있다. 파이썬 휠을 기본 설정으로 빌드하면 비상업 Triangle과 GPL 모듈(`igl.triangle`, `igl.copyleft`)이 함께 들어간다 ([CMakeLists.txt](https://github.com/libigl/libigl-python-bindings/blob/main/CMakeLists.txt)). 가장 안전한 길은 그 옵션을 끄고 직접 빌드하거나, BBW만 우리 코드로 옮기는 것이다. 반대로 **피해야 할 것**도 분명하다. Shewchuk Triangle은 "상업 제품에 포함 불가"라고 적혀 있다 ([Triangle](https://www.cs.cmu.edu/~quake/triangle.html)). 그래서 Triangle을 감싼 `triangle`·`meshpy`·`igl.triangle`, Monster Mash 빌드는 쓰지 않는다. Spine 런타임은 사용자마다 에디터 라이선스가 필요하다 ([spine-runtimes LICENSE](https://github.com/EsotericSoftware/spine-runtimes/blob/master/LICENSE)). GPL인 kimimaro·puppet-warp, 라이선스가 없는 DrawingSpinUp·AniClipart·Sketch2Pose, 학습 모델이 비상업인 InsightFace도 뺀다.

구조 면에서 가장 큰 개선은 **"서버는 메시와 프레임 좌표(또는 뼈와 가중치) JSON만 보내고, 그리기는 브라우저 Pixi가 하는 것"**이다. 지금처럼 서버가 영상을 굽는 방식보다 서버 비용과 대기 시간이 함께 준다. 뱀·지렁이 꿈틀은 Pixi `MeshRope`에 몸통 중심선을 제어점으로 넘기면 서버 계산 없이 된다. 단, 굽은 그림은 먼저 축을 따라 펴는 전처리가 필요하다.

## 단계별 움직임과 S-06 확장은 조사 결과가 지지한다

교수님 지적("비휴머노이드가 주인공이면 캐릭터가 아예 없는데 서비스가 무슨 의미냐")에 대해 이번 조사가 주는 답은 이렇다. **시장 전체가 비휴머노이드를 "다시 그린 영상"이나 "미리 만든 도안"으로 피해 갔고, 아이가 그린 그 그림 자체를 움직이는 곳은 없다.** 바로 그 빈자리가 우리 차별점이다. 단계별 움직임(사람 → 네발 → 긴 몸 → 몸통만 통통·흔들)은 이 빈자리를 채우는 현실적인 설계다. 마지막 "몸통만" 단계는 테두리만 있으면 되므로 항상 성공한다. 별·구름·형태 불명 괴물에는 오히려 부위가 없는 이 방식이 맞다. 숨쉬기·흔들기·squash & stretch는 메시 정점 변환만으로 충분하다. MLS와 shape matching은 이 단계를 "그냥 흔들림"보다 살아 있는 느낌으로 올려 줄 검증된 방법이다. 다만 교수님 지적에도 일리가 있다. 몸통만 움직이는 주인공은 걷기·날기 같은 이야기 동작을 못 한다. 그러니 이 단계는 "실패해도 빈 화면은 없다"는 안전망으로 두고, 되도록 많은 그림을 앞 단계로 올리는 것이 목표가 되어야 한다.

S-06 확장(자동 인식이 자신 없을 때만 보호자가 종류 카드를 고르고, 미리 놓인 점을 고침)도 근거가 탄탄하다. 첫째, 연구계가 이미지 언어 모델의 부위 수준 포인팅이 약하다고 보고한다. 그러니 "자동 + 사람 확인"이 "완전 자동"보다 정직한 설계다. 둘째, 범주 무관 키포인트 모델(PoseAnything·CapeX)은 원래 "종류별 기준 그림 한 장"을 요구한다. 보호자가 "네발", "새", "긴 몸" 카드를 고르는 순간이 곧 그 기준 그림을 고르는 순간이 된다. 카드 고르기가 UX 장치이면서 동시에 모델 입력이 되는 셈이다. 셋째, 상용 도구 중 동물을 다루는 Cartoon Animator도 결국 "네발 템플릿을 고르고 맞추는" 방식이다. 우리 카드는 그 과정을 보호자 한 번의 선택으로 줄인 것이다. 건너뛰면 몸통만 단계로 가는 규칙은 사람 손 없는 자동이라는 원칙도 지킨다. 남은 불확실성은 하나다. 아이 동물 그림에서 우리 자동 인식이 얼마나 자주 "자신 있음"을 낼지 실측한 적이 없다. 그 비율이 낮으면 S-06이 사실상 필수 화면이 되므로, 아래 첫 실험이 이 값을 재야 한다. 이 방향은 팀 설계 문서(pt_docs)의 S-06 정의와 맞춰 팀 논의로 확정해야 한다.

다음 할 일을 효과 대비 비용 순으로 정리하면 아래와 같다.

| 순서 | 할 일 | 필요한 것 | 확인할 값 |
|---|---|---|---|
| 1 | 동물·괴물 그림 표본(예: 30~50장)으로 단계별 판정과 "자신 있음" 비율 재기 | 기존 `drawings`, `drawings_quad` | 단계별 성공률, S-06으로 가는 비율 |
| 2 | skan 또는 DSE로 뼈대 잔가지 치기를 `shape_rig.py`에 넣기 | pip `skan` | 가지 수, 다리·꼬리 오검출 감소 |
| 3 | 다리가 붙어 움직이는 그림에 PythonCDT 경계 구속 메시 적용 | pip `PythonCDT`(휠 여부 확인) | 다리 사이 삼각형 제거 |
| 4 | 몸통만 단계 완성: 숨쉬기·흔들기·squash & stretch + 감쇠 스프링 2차 움직임 | 직접 구현, 필요 시 MLS | 모든 그림에서 실패 0 |
| 5 | Pixi v8 `MeshSimple`로 ARAP 프레임 JSON 재생 시제품, 뱀은 `MeshRope` | 프론트 저장소 | 저가 폰 재생, JSON 크기 |
| 6 | S-06 확장 화면 설계: 종류 카드 + 가지 끝·덩어리 중심에서 미리 놓은 점 | pt_docs 05 화면설계서와 대조 | 보호자 조작 횟수 |
| 7 | 번호 점 분류 시험(set-of-marks): 로컬 [Molmo-7B-D](https://huggingface.co/allenai/Molmo-7B-D-0924)(Apache-2.0이지만 "연구·교육용" 안내와 Qwen 라이선스 확인 필요, GPU) 또는 유료 모델 | **유료 API는 모델·횟수·금액 승인 후** | 머리·꼬리·다리 분류 정확도 |
| 8 | ChildlikeSHAPES 압축을 풀어 25개 부위 목록 확인 → SAM 2 미세조정 가치 판단 | 디스크 약 20GB 이상([Releases](https://github.com/facebookresearch/AnimatedDrawings/releases), 조각당 1.95GB) | 꼬리·날개 라벨 유무 |
| 9 | (선택) 생성 영상 비교군 5장 시험, 아이 그림 보존 정도 기록 | 승인 후 최저가 모델 | "내 그림" 유지 여부 |

## Conclusion

이번 조사는 "비휴머노이드 2D 자동 리깅은 누군가 이미 만들었을 것"이라는 가정을 깼다. 상용 시장은 정확히 우리가 원하는 칸을 비워 두고 있다. 이유는 기술 수준보다 정책에 가깝다. 생성 영상 회사들은 아이 그림을 다시 그려서 문제를 피했고, 그 대가로 그림이 변하고 아동 대상 약관에 걸린다. 리깅 도구 회사들은 사람 손을 전제로 해서 자동화를 하지 않았다. 그러니 우리 쪽 일은 "기성품을 찾아 붙이기"가 아니다. 이미 있는 모양 뼈대 노선을 검증된 작은 부품으로 단단하게 만들고, 자동이 모자란 순간을 보호자의 한 번 선택으로 메우는 것이다.

교수님 질문에 대한 가장 강한 답은 기술 설명이 아니라 숫자가 될 것이다. 동물·괴물 그림 표본에서 몇 %가 네발·긴 몸 단계로 제대로 움직이고, 몇 %가 S-06 카드 한 번으로 올라가고, 몸통만 단계로 남는 것은 몇 %인지 보여 주면 된다. 그 숫자가 "비휴머노이드 주인공도 자기 그림 그대로 움직인다"는 주장을 증명하거나, 어디에 힘을 더 써야 하는지 알려 줄 것이다.
