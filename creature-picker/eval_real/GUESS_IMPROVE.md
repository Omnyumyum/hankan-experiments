# 종류 자동 추측 고치기 (2026-10-27)

**한 줄 요약:** QuickDraw 마지막 확인용 1000장에서 추측이 **맞은 것 29% → 47%**, **틀린 것 20% → 4.5%**, 모르겠음 51% → 49%.
틀린 것은 10 카테고리 **모두에서** 줄었다. 대신 아직 색칠한 아이 그림으로는 거의 재 보지 못했다(아래 「아직 안 되는 것」).

## 무엇을 바꿨나
- `rig_types.propose` 의 추측 부분만 바꿨다. **점 미리 놓기 · 움직이기는 그대로**다(그래서 아래 기존 검사 결과도 같다).
- 예전: 「다리 3개 이상 → 네 발 / 긴 몸 판정 → 긴 몸 / 튀어나온 곳 없음 → 몸통만 / 양옆 두 갈래가 비슷 → 날개」 4줄 규칙.
- 지금:
  1. `guess_features` — 그림에서 숫자 24개를 잰다. 예전 규칙이 보던 것(다리 수, 긴 몸 판정, 튀어나온 곳 수 · 길이)에
     모양 숫자를 더했다: 볼록 껍질 대비 넓이(구름은 높고 별 · 다리 있는 그림은 낮음), 좌우 · 위아래 대칭, 가장 굵은 곳,
     몸 안 선 밀도(수염 · 줄무늬), 칸 수, 튀어나온 곳들이 둘레에 고르게 퍼졌는지(별), 갈래 방향(위 · 옆 · 아래), 발이 바닥에 있는지 등.
  2. `guess_proba` — 작은 결정 나무 묶음(gradient boosting, 깊이 3 나무 80개 × 4종)이 종류마다 확률을 낸다.
     나무는 `guess_model.json`(180KB)에 들어 있고 numpy 로만 읽는다(새 설치 없음). scikit-learn 과 확률 차이 0.0 확인.
  3. **가장 높은 확률이 0.8 미만이면 None(모르겠음).** 틀리게 확신하는 게 더 나쁘다는 규칙을 그대로 기준에 넣었다.
     0.8 은 학습용 안 교차 검증으로 골랐다(0.7: 맞음 574 / 틀림 75, **0.8: 470 / 33**, 0.9: 326 / 9 — 1000장 중).
- 모델 파일이 없으면 예전 규칙(`guess_rules`, 비교용으로 남김)으로 돌아간다.
- 덤으로 고친 것: 예전 코드에서 다리를 못 찾았을 때 대신 놓은 발 4개가 「다리 수」로 세지지 않게 따로 셌다(추측 특징에만 영향).

## 어떻게 쟀나 (한 그림에 맞추지 않기)
- QuickDraw `full/simplified` 10 카테고리 파일 앞 30MB 씩(인식된 그림만, 카테고리마다 3.8만~8.9만 장).
  카테고리마다 섞어서(seed 11) **학습용 100 · 확인용 100 · 마지막 확인용 100** 장, 서로 겹치지 않는 다른 그림.
  그리는 방법은 `run_eval.py` 와 같다(흰 종이 · 검은 선 6px · 400px).
- 학습용: 모델을 배우고 0.8 기준을 고를 때만 썼다.
- 확인용: 모델 종류(나무 하나 · 랜덤 포레스트 · 로지스틱 회귀 · gradient boosting)를 비교할 때 봤다 → 여기 숫자는 조금 좋게 나왔을 수 있다.
- **마지막 확인용: 모든 걸 정한 뒤 한 번만 쟀다.** 아래 비교는 이 숫자를 기준으로 본다.
- 「기대 종류」는 카테고리 이름으로 정했다(dog · cat · horse · pig → 네 발, snake → 긴 몸, bird · butterfly · bee → 날개, cloud · star → 몸통만).
  얼굴만 그린 고양이도 「네 발」이 정답이라 실제보다 엄하게 매긴 셈이다.
- 다시 재기: `venv/bin/python -I eval_real/guess_eval.py --qd 받은폴더 --split all [--old]`,
  모델 다시 만들기: `venv/bin/pip install scikit-learn` 후 `venv/bin/python -I eval_real/train_guess.py --qd 받은폴더`.
  그림마다 결과: `guess_old.csv` · `guess_new.csv`. 받은 ndjson · 그린 PNG 는 올리지 않았다.

## 아직 안 되는 것
1. **색칠한 아이 그림으로는 거의 안 쟀다.** 모델은 QuickDraw(마우스 · 선만 · 칠 없음)로만 배웠다. 「선 밀도」「칸 수」 같은 숫자는
   색칠 · 크레파스 그림에서 값이 크게 다를 수 있다. 우리 그림 16장에서 틀림 0 이었지만 16장은 너무 적다.
   Meta Amateur Drawings 같은 실제 아이 그림으로 다시 재야 한다(네트워크가 열리는 환경에서 `guess_eval.py` 입력만 바꾸면 됨).
2. **모르겠음이 여전히 절반(49%).** 특히 새(bird)는 81% 가 None, 맞힌 건 9% 뿐이고 틀림(10장, 대부분 네 발)이 맞음보다 많다.
   옆모습 새 낙서는 다리 두 개 + 날개가 접혀 있어 네 발 · 몸통만과 구별이 안 된다. 「사람이 고른다」는 흐름은 그대로 필요하다.
3. 「자신 있으면 카드 없이 바로 움직이기」는 아직 이르다: 추측을 낸 것 중 9% 는 틀린다(새 · 벌 · 별 · 개에서 몇 장씩).
4. 기대 종류를 카테고리 이름으로 정해서, 얼굴만 그린 고양이 · 돼지도 「네 발」이 정답으로 들어 있다. 모델이 「얼굴 → 네 발」을 배웠을 수 있다
   — 얼굴만 그린 그림을 네 발로 움직이면 크게 늘어난다(REPORT.md 실패 1번). 추측을 믿고 바로 움직이기 전에 따로 확인해야 한다.
5. 학습 그림은 카테고리마다 100장(1000장)뿐이고, 파일 앞 30MB 만 써서 완전한 무작위는 아니다. 모델 · 기준은 이 데이터에 맞춘 것이다.
