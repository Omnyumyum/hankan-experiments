# 4차 합치기 — 찾기 상자 + 「자동 먼저 → 틀리면 누름」 (2026-10-29)

**한 줄 요약:** Meta 사람 그림 찾기 모델의 상자 안에서만 모양을 따면 마스크 실패가 모든 확인용 묶음에서 줄었다(사람 아닌 그림 25 → 22%, 사진 전체 7,000장 넘게 합쳐 1,041 → 822장).
여기에 「상자 안 마스크와 사진 전체 마스크가 많이 다르면 누름을 묻기」를 더하면 더 준다(사람 아닌 그림 → 19%, 합계 → 764장). 이때 어른이 누르는 것은 **그림 100장에 3 ~ 14번**이다.
「누름만」(찾기 상자 없이)은 정답을 안 보고 「틀렸다」를 알아낼 신호를 학습용에서 찾지 못해 지금과 같다. 깨끗한 그림(QuickDraw 원본)은 나빠지지 않았지만 **크레파스 결 · 줄 공책 변환은 조금 나빠졌다**(6 → 8, 7 → 9장 / 300).
CPU 한 장 시간은 찾기 모델 2.2초(4스레드) · 5.0초(1스레드)가 대부분이다. 기존 검사 숫자는 모두 3차 그대로다.

## 2. 규칙 (학습용에서만 보고 정함)
- **여백**: 찾기 상자를 너비 · 높이의 10% 넓혀 잘라 `Drawing`. 학습용 네 묶음 실패 합(상자를 늘 씀): 여백 0 → 597, **0.1 → 384**, 0.2 → 389, 0.35 → 405, 0.5 → 428 (지금 445).
  사람 그림(TAP)만은 0.2 가 나았지만(70 대 63) 합으로 골랐다.
- **상자 버리기** (사용자 요청 2): 상자가 없거나, 상자 안 마스크가 비었거나, **상자 안 마스크와 사진 전체 마스크의 IoU < 0.1** 이면 상자를 버리고 지금 방식.
  점수 하한(0.7 ~ 0.99) · 상자 넓이 하한 · 마스크 상자와 찾기 상자 IoU 하한도 같이 격자로 봤지만 학습용 합이 1장 넘게 줄지 않아 넣지 않았다(규칙 없이 상자를 늘 쓰면 384, 이 규칙이면 374, 가장 좋은 조합도 373).
- **누름 묻기** (서비스에서 알 수 있는 값만): 상자를 썼는데 **상자 안 마스크와 사진 전체 마스크의 IoU < 0.4** 이면 「그림 한가운데를 눌러 주세요」. 상자를 안 썼으면 마스크가 비었을 때만.
  - 고른 기준(학습용 결과를 보기 전에 정함): `실패 장수 + 0.25 × 물은 장수` 가 가장 작은 것(실패 하나를 막는 값 = 누름 네 번).
  - 견준 신호: 두 마스크 IoU · 「누르지 않고 찾기 상자만 MobileSAM 에 넣은 마스크」와의 IoU · 찾기 점수 · 둘의 조합, 문턱 0.3 ~ 0.95, 상자를 안 쓴 그림은 늘 물음 / 안 물음 / MobileSAM 신호.
    학습용 1,931장에서 안 물음 374 → 고른 규칙 332(물음 149) · MobileSAM 신호 0.3 → 350(물음 110) · 찾기 점수(상자를 안 쓴 그림은 늘 물음) → 377 이상 · 모든 그림에 물음 351(1,931번).
  - **누름만(찾기 상자 없이)**: 쓸 수 있는 신호는 마스크 넓이뿐인데, 모든 문턱에서 「안 물음」보다 비용이 컸다(444 대 456 ~ 610). 그래서 누름만 갈래는 **묻지 않음 = 지금과 같음**이다.
- **누름**: TAP_SEGMENT 와 같은 사람 흉내(정답 안 깊은 곳 무작위 한 점 + 손떨림 긴 변 2%, 그림마다 seed 고정) · MobileSAM(clean_photo 그림 입력) · 최종 후처리(guardbbig@base+fill).
  상자를 쓴 그림은 **사진 전체에 「누른 점 + 찾기 상자」를 같이** 넣는다. 학습용에서 늘 누를 때 실패: 점 + 상자 351 · 상자 안 그림만 넣고 점 614 · 사진 전체에 점만 557.
  (TAP_SEGMENT 는 「종이 상자 · clean_photo 상자를 같이 주면 종이를 잡는다」고 했는데, 찾기 상자는 그림에 딱 맞아 그 문제가 없다.)

**주의 — Meta 숫자는 좋게 나올 수 있다:**
① 찾기 모델은 Meta 가 같은 앱에서 모은 그림으로 학습했다(설정 파일의 학습 데이터 경로 `AD_Consent_Data`). Amateur Drawings 그림 일부를 학습 때 봤을 수 있다 → **상자가 실제 사진보다 잘 맞게 나올 수 있다.**
② **Meta 정답 마스크는 Meta segment() 쪽으로 기울어 있는 것으로 보인다.** 상자 + Meta segment() 는 Meta 묶음에서 가장 좋았지만(사람 아닌 그림 확인용 실패 16%) 정답이 따로 그려진 QuickDraw 에서는 31% 로 가장 나빴다(우리 방식 7%). 정답이 앱의 자동 마스크를 사람이 고친 것이라서로 보인다(확인 안 함). 미리 재 주신 18/68 과도 맞지 않는다 — 그쪽은 IoU 계산 방식이 달랐을 수 있다.

### 사람 아닌 그림 묶음 (사용자가 잰 68장 대신 새로 만든 것, `box_nonhuman_labels.csv`)
미리 잰 68장은 저장소에 없어 같은 묶음을 쓸 수 없었다. 같은 생각으로 다시 골랐다:
1. 위 11,786장을 index 순서대로 100장씩 모아 보기(정답 마스크 둘레로 잘라 키움)로 **전부** 눈으로 봤다(`box_pick.py`). 사람이 아닐 수 있는 것은 모두 후보로(1,135장).
2. 후보를 큰 모아 보기로 다시 보고 남겼다. **뺀 것**: 사람처럼 머리 · 몸통 · 두 팔 · 두 다리로 선 것(곰 · 고양이 · 토끼가 서 있는 그림 포함), 사람과 같이 그린 것 중 사람이 주인공인 것, 물건(자전거 · 수레).
   **남긴 것**: 날개(새 · 나비 · 벌 · 박쥐 · 펭귄), 네 발(옆모습 · 엎드린 동물, 공룡), 덩어리(유령 · 얼굴만 · 눈사람 · 과일 · 하트 · 별, 몸통에 막대 팔다리가 붙은 것), 긴 몸(물고기 · 뱀 · 달팽이 · 해마).
3. 학습 · 확인 = 파일 이름 md5 첫 글자 짝 · 홀(FAINT_RULED 와 같은 규칙). 정답 마스크는 보지 않고 골랐다.

## 7. 눈으로 본 모아 보기
- **`sheet_box_qd.jpg`** (QuickDraw 확인용, CC BY 4.0, 올림). 한 줄 = 사진(초록 정답 윤곽 · 파랑 찾기 상자 · 빨간 누른 점) | 지금 | 상자 안 | 상자 + 누름 최종, 마스크는 초록 = 정답만 · 빨강 = 잡은 것만 · 노랑 = 둘 다.
  위 6줄 = 상자가 망친 것, 가운데 6줄 = 상자가 고친 것, 아래 6줄 = 누름을 물은 것.
  - 상자가 망치는 경우 두 가지: ① **상자가 그림 일부만 덮음**(dog9 크레파스 — 머리만 상자), ② **상자로 자르면 몸 안쪽 채우기가 빠짐**(dog12 줄 공책 · horse5 연한 연필 · bird18 — 선만 남음). ②는 두 마스크 IoU 가 낮아 대부분 누름으로 고쳐진다(dog12 0.27 → 0.71, horse5 0.22 → 0.81). ①은 사진 전체 마스크와 겹쳐 IoU 가 높아 안 걸린다.
  - 상자가 고치는 경우: 나쁜 사진에서 **종이 밖 · 배경까지 번지던 마스크**가 상자 안으로 줄어든다(pig19 0.15 → 0.69, butterfly25 0.23 → 0.93).
- Meta 모아 보기(재기용, 올리지 않음 — `box_sheet.py --set nh_check --pick 상자망침|남은실패`):
  - 상자가 망친 5장 중 4장은 위 ②(눈사람 · 펭귄 · 돼지 몸 안쪽이 빠짐)이고 모두 누름으로 고쳐졌다.
  - **사람과 동물을 같이 그린 그림에서 찾기 모델이 사람을 고른다**(meta1908: 사람 + 고양이 → 사람 상자). 사람 그림 찾기 모델이라 당연하다.

## 8. 아직 안 되는 것
1. **찾기 상자 없이 「틀렸다」를 알아낼 신호가 없다** → 「누름만」 갈래는 지금과 같다. 상자를 쓰는 신호(두 마스크가 다름)도 학습용에서 가능한 몫(사람이 보고 누름 261)의 절반쯤만 잡는다(374 → 332).
2. **크레파스 결 · 줄 공책 QuickDraw 변환이 2장씩 나빠졌다.** 원인 ①(상자가 일부만 덮음)은 두 마스크가 겹쳐 신호에 안 걸린다. 「상자 밖에도 지금 마스크가 많이 남으면 상자 버리기」 같은 규칙을 **새 학습용**으로 봐야 한다.
3. **상자로 자르면 몸 안쪽 채우기가 빠지는 경우**(원인 ②)는 누름으로 고치고 있지만 자동으로 막는 것이 낫다. 자른 그림은 종이 둘레가 거의 없어 `clean_photo` · `crop_and_mask` 의 판단이 달라지는 것으로 보인다(열어 보지 않음).
4. **사람 + 동물 그림에서 사람을 고른다.** 동물이 주인공인 사진은 상자를 버려야 하는데 지금 규칙은 모른다. 찾기 모델을 동물 그림으로 다시 학습하거나, 상자 후보 여럿 중 고르게 해야 한다.
5. **Meta 숫자가 좋게 나올 수 있다** (3절 ① 찾기 모델이 본 그림일 수 있음, ② 정답이 Meta segment() 쪽으로 기움). 실제 서비스 사진으로 다시 재야 한다. 같은 까닭으로 「Meta 상자 + Meta segment()」가 낫다는 Meta 숫자는 믿지 않았다.
6. 사람 아닌 그림 묶음은 한 사람(이 작업)이 눈으로 골랐고 덩어리가 60% 다. 사용자의 68장과 장수 · 비율이 다르다.
7. 누름은 한 번만 흉내냈다. 두 번째 누름을 언제 물을지, 실제 사람이 어디를 누르는지는 모른다(TAP_SEGMENT 「아직 안 되는 것」 6 그대로).
8. 찾기 2.2초(1스레드 5초)가 무겁다. 넣는 크기를 줄이는 것 · 서버 여러 사용자 동시 처리는 재지 않았다. `find_box.py` 가 mmdet 원본과 숫자까지 같은지도 직접 견주지 못했다(1절).
9. 화면(누름 안내 · 누른 점 받기)은 만들지 않았다. `box_first.py` 는 「물을지」까지만 알려 준다.
