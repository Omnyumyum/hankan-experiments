# 친구 종류 고르기 시험판 (2026-10-26 ~ 10-27)

비휴머노이드 그림을 **어른이 종류를 고르고 → 미리 놓인 점을 고치면 → 움직이는** 흐름을 실제로 돌려 보는 로컬 시험판.
S-06(관절 고치기, 어른 화면)을 넓히는 가안이다. git 아님, 팀 저장소 · 팀 문서와 상관없다 (관절 작업은 로컬에만 기록).

배경: 지도 교수님 지적 「비휴머노이드가 주인공이면 캐릭터가 아예 없는데 서비스가 무슨 의미냐」.
2D 기성 해법 조사 결과는 `../animal-monster/reports/2D 비휴머노이드 자동 리깅 조사.md` — 그림 한 장 · 자동 · 2D 그대로 · 비휴머노이드 · 상업 라이선스를 다 갖춘 것은 없었다.

## 흐름

1. 그림 고르기 (파일 올리기 또는 시험 그림)
2. **두 발로 선 친구 / 다른 모양 친구** — 두 발이면 기존 흐름(Meta 15관절)으로 넘긴다는 안내만 (이 시험판은 비휴머노이드만)
3. **네 발 · 긴 몸 · 날개 · 몸통만** — AI 추측 카드에 표시만 하고 고르는 건 사람
4. 점 확인: 자동으로 미리 놓은 점을 끌어서 고친다 (몸통만은 건너뜀)
   - 네 발: 머리, 꼬리(없으면 끔), 발 끝 2~6개
   - 긴 몸: 머리, 꼬리 끝 (몸 축은 자동)
   - 날개: **칸 고르기**(기본) — 움직일 날개 칸을 누르거나 문지른다. 뿌리는 자동(끌어서 옮길 수 있음).
     선이 크게 끊긴 그림이면 「점 3개」(뿌리 위 · 뿌리 아래 · 날개 끝)로 바꾼다. 날개짓 방식(위아래 / 접었다 폈다)도 고른다
5. 움직여 보기 — 서버는 프레임별 꼭짓점만 보내고 브라우저(PixiJS `MeshSimple`)가 그린다

| 종류 | 움직임 | 코드 |
|---|---|---|
| 네 발 | CMU 걸음 곡선으로 걷기, 머리 끄덕 · 꼬리 흔들 | `quadruped.pose` 그대로, 기준점만 사용자 점에서 |
| 긴 몸 | 축 따라 꿈틀 | `shape_rig.pose_body` 그대로 |
| 날개 | **위아래**(앞모습 · 옆모습 새: 경첩 가운데를 축으로 회전, 무게만큼 각도를 나눠 어깨에서 둥글게 휨) 또는 **접었다 폈다**(위에서 본 나비: 경첩에서 먼 거리만 cos 만큼 줄임). 날개 폭/길이가 0.45 넘으면 접었다 폈다로 미리 고름 | 새로 (`rig_types.build_wings`). **ARAP 를 안 쓰고 꼭짓점을 직접 옮긴다** — ARAP 는 모양을 지키려 버텨서 날개를 좁히면 말려 들어갔고, 뿌리가 날개 안쪽에 생겨 날개가 중간에서 휘었다 |
| 몸통만 | 통통 · 말랑 + 위쪽이 늦게 따라오는 출렁임 | `shape_rig.pose` + 늦은 자세 섞기 |

## 날개 칸 고르기 (2026-10-26 ~ 27)

색칠 공부 그림 · 윤곽선으로 그린 아이 그림은 날개 · 몸 · 머리가 **선으로 닫힌 칸**으로 나뉜다. 페인트 통으로 칸을 채우듯 날개 칸을 고르게 한다.
점 3개 방식은 뿌리 점을 몸 안쪽에 두면 몸통도 날개로 잡혔고(점만으로는 구분할 근거가 없음), 비스듬한 나비(test_butterfly_coloring)처럼
날개 여러 장이 한쪽에 겹친 그림은 아예 안 됐다.

| 단계 | 하는 일 | 왜 (시험 세트에서 깨졌던 것) |
|---|---|---|
| 칸 나누기 `region_labels` | 선 = 결을 지운 그림의 어두운 선(작은 점 조각 버림) + 길게 이어진 색 경계. 그림 바깥 둘레 띠는 칸이 아니라 선 | 크레파스 결이 날개를 자잘하게 쪼갬 · 윤곽선 없는 크레파스 날개는 칸이 안 생김 · 바깥 띠를 칸으로 두면 날개 테두리가 안 움직임 |
| 고르기 | 누르기 = 한 칸, 문지르기 = 지나간 칸 전부. 시작한 칸이 이미 골라져 있으면 지우기 | 「전부 골라져 있으면 빼기」는 이어 칠하다 지워짐 |
| 날개 범위 `wing_regions` | 고른 칸 + 날개 칸 **하나**에 갇힌 무늬 칸 + 가까운 선(몸과 맞닿은 선은 몸 것, 검게 칠한 덩어리는 아무 칸 것도 아님) | 양쪽 날개 사이 몸통 · 날개가 감싼 머리가 「갇힌 칸」이 됨 · 맞닿은 선을 반씩 나누면 몸 윤곽선이 끊김 |
| 날개 나누기 `wing_groups` | 경계를 둘레의 12% 넘게 나눠 갖는 칸끼리 한 날개. 닿아 있고 같은 쪽으로 뻗은 덩어리는 합침 | 머리 위에서 점처럼 닿는 좌우 날개가 한 덩어리 → 한쪽으로 쏠림 · 비스듬한 나비 앞뒤 날개가 따로 → 사이가 벌어짐 |
| 뿌리 `crowd_root` | 몸 「칸」과 선 하나 사이로 맞닿은 곳 중 날개 칸이 가장 많이 모인 점 | 맞닿은 곳 가운데 → 앞날개 한가운데 · 테두리 선까지 세면 뿌리가 날개 끝 |
| 메시 자르기 `cut_mesh` | 날개와 다른 부분이 맞닿은 곳의 꼭짓점을 둘로. 뿌리 둘레만 붙임. 그리는 순서: 날개 먼저 · 몸 나중 | 좌우 날개가 서로 파고들어 삼각형 뒤집힘 → 이제 겹치면 날개가 몸 뒤로 |
| 무게 `vertex_weights` | 위아래 = 뿌리에서 날개 길이 45% 에 걸쳐 오름 · 접기 = 경첩에서 바깥으로 조금씩 줄여 쌓기(누적표). 안 붙은 테두리 꼭짓점은 이웃 평균 | 급한 무게 → 뒤집힘 · 「거리 × 무게」 접기 → 바깥 점이 안쪽 점을 앞질러 뒤집힘 · 날개 끝 테두리 혼자 가만히 → 15~20배 늘어남 |

### 경우의 수 시험 세트 (`gen_wing_cases.py` · `check_wings.py`)

그림 하나에 맞춰 고치면 다른 그림이 깨지는 일을 되풀이해서 만들었다. 그림 9장 × 날개짓 2방식 = **18 조합**을 고칠 때마다 전부 돌린다.

- 그림: 비스듬한 색칠 나비 · 앞모습 새 · 위에서 본 나비 · 옆모습 새 (기존) + 선만 있는 나비(갇힌 무늬) · 윤곽선 끊긴 새 · 몸에서 떨어진 날개(요정) · 윤곽선 없는 크레파스 날개 · 날개 네 장 잠자리 (생성)
- 판정: 움직여야 할 점 무게 ≥ 0.6 · 가만히 있어야 할 점 ≤ 0.15 · 날개 덩어리 수 · 날개 안 빈 곳 ≤ 3% · 가장 많이 늘어난 모서리 ≤ 5배 · 뒤집힌 삼각형 ≤ 1%
- 미리보기(`check.warp_in_order`)는 브라우저처럼 삼각형을 순서대로 그린다 (shape_rig.warp 는 순서를 무시해 날개가 몸 뒤로 가는지 볼 수 없었다)
- 2026-10-27 결과: **18/18 통과**, 늘어남 최대 2.2배. 다른 종류 40 조합(`check.py`)도 그대로 돈다
- 숫자 검사가 놓친 것은 눈으로 보고 검사 항목을 더했다 (날개 안 빈 곳 · 뒤집힌 삼각형 · 날개 덩어리 수 · 늘어남 기준)

## 점 위치 흔들기 검사 (2026-10-27) — 「점이 조금 빗나가면 이상해진다」

점마다 반경 R 안에서 무작위로 흔들어 돌리고, 정답 점일 때와 같은 기준으로 판정한다.
- 날개 `check_wing_points.py`: 몸통이 딸려 오지 않고 날개가 움직이고 찢김 · 뭉개짐이 없나
- 네 발 · 긴 몸 `check_points_jitter.py`: 정답 점 움직임과 꼭짓점별 어긋남(상위 5% 평균)이 그림 긴 변의 3% 이하인가 + 찢김 · 뭉개짐

| 종류 | 고치기 전 (R=10 / 16) | 고친 뒤 (R=10 / 16) | 고친 것 |
|---|---|---|---|
| 날개 (8장) | 11% / 11% | **96% / 93%** | 점 3개 → 칸에 맞춤 (`snap_points_to_regions`): 날개 끝이 든 칸에서 시작해 경계를 길게 나눠 갖는 칸으로 넓히고, 경첩 안쪽(몸 쪽) 칸에서 멈춘다. 뿌리 두 점은 어느 쪽이 몸인지만 알려 주면 된다. 칸이 안 생기는 그림만 점 3개 그대로 |
| 네 발 (6장) · 긴 몸 (3장) | 93% / 89% | **100% / 100%** | 점을 그림의 끝(가지친 뼈대 끝점)에 맞춤 (`snap_to_tips`). 발은 아래쪽 끝점과 한꺼번에 최적 짝짓기 — 하나씩 붙이면 두 발이 한 다리에 몰렸다 (막대 다리 개 그림) |

- 점 3개 그대로는 정답 점으로도 대부분 실패했다: 날개가 몸에 붙은 폭이 뿌리 두 점보다 조금만 넓어도 날개 대부분을 「경첩 구간 밖」으로 봤다
- 날개를 칸에 맞추며 고친 것: 날개 끝 점은 보통 테두리 선 위라 선 굵기 3배 안에서 칸을 찾는다 · 칸의 70% 넘게가 경첩 바깥이어야 날개(절반이면 가는 몸통이 들어옴) · 안팎은 경첩 구간 둘레 띠에서만 보고, 칸 중심이 구간 너머면 넘어간 거리의 30% 넘게 바깥이어야 함(배 끝 · 긴 몸통 빠짐). 픽셀마다 부채꼴로 세는 기준은 휘감긴 날개 칸을 빼서 버렸다
- 남은 약점: **비스듬한 색칠 나비** 6/9 · 4/9 — 날개 여러 장이 뿌리 한 점으로 모이고 배가 경첩 선 연장선 위에 놓여, 뿌리 점이 흔들리면 배 끝이 들어오거나 날개 한 장이 빠진다. 이런 그림은 칸 고르기가 낫다

## 확인한 것 (2026-10-26)

- 시험 그림 10장(animal-monster 8장 + 날개 2장) × 4종 = 40개 모두 끝까지 돈다. 움직임 하나 서버 0.1~0.5초 (첫 호출만 skan/numba 준비로 약 2초)
- 브라우저: 개 → 다른 모양 → 네 발 → 움직여 보기, 나비 → 날개 → 점 끌기 → 움직여 보기까지 실제로 눌러 봄. Pixi 재생 · 기준점 보기 동작
- 점이 맞으면: 개 · 말 · 돼지 걷기, 뱀 · 지렁이 꿈틀, 앞모습 새 날개짓(위아래), 나비 접었다 폈다, 덩어리 괴물 말랑 모두 됨
- 떨어져 그린 머리(개)는 네 발용 마스크(`open_gaps`)에서 몸과 끊긴다 → 몸 안 길이 없으면 곧은 선으로 이어 기준점을 둔다

## 안 되는 것 · 남은 것

- **옆모습 새**: 「날개 하나만」 + 뿌리 두 점을 **등을 따라**(날개 뿌리 앞 · 뒤), 끝은 날개 끝에 놓으면 머리 · 배는 가만히 있고 등 위로 튀어나온 날개만 통째로 움직인다 (animal_bird 확인). 몸 윤곽 안에 선으로만 그린 날개 부분은 떼어 내지 못해 그대로다
- 날개 무게 정하기 (2026-10-26 여러 번 고침): ① 경첩 선을 끝없이 늘려 선 바깥을 다 날개로 침 → 옆모습 새 머리 · 배가 그네를 탐. ② 부채꼴 + 닿은 조각 → 부채꼴 선에서 기괴하게 꺾임. ③ **지금**: 점 3개(뿌리 위 · 아래 · 끝) + 그림 안 거리. 무게 = (몸에서 오는 길이 경첩 구간을 지나 오는가: 구간 밖 선을 넘어 오면 0 — 경첩 옆에 붙은 머리) × (경첩→날개 끝 거리 비율: 3% 부터 휘기 시작 · 25% 부터 통째로). 모양으로 긋는 선이 없어 경계에서 찢기거나 꺾이지 않는다. 앞모습 새는 날개를 끝까지 올릴 때 어깨에 작은 틈이 살짝 보인다
- **뿌리 점을 몸 안쪽에 두면 몸통도 같이 움직인다**: 경첩이 몸을 가로지르면 경첩과 날개 끝 사이의 몸통도 기하학적으로 「날개 쪽」이라 점만으로는 막을 수 없다 (몸 안에 그린 날개 선은 보통 끝이 열려 있어 선으로 가르지도 못함). 그래서 점 고치기 화면에 **움직일 범위를 빨갛게** 겹쳐 보여 준다 (`/api/weights`, 점을 끄는 동안 0.18초마다 · 놓을 때 갱신). 안내: 뿌리 두 점은 날개가 몸에서 빠져나오는 곳(몸 윤곽선 쪽)에
- **칸 고르기의 한계**: 선이 크게(약 4px 넘게) 끊기면 그 칸이 바깥과 이어져 칸이 안 된다 (윤곽선 끊긴 새의 왼쪽 날개) → 점 3개 방식.
  문지르다 빠진 줄무늬는 자동으로 안 채운다(자동 규칙은 몸통까지 끌어들여서 뺐다) — 화면에서 빨간 날개 안의 흰 칸으로 보이니 눌러 채운다.
  날개를 끝까지 내릴 때 머리 옆에 작은 조각이 남는 경우가 있다 (위에서 본 나비 · 비스듬한 나비)
- **AI 추측은 힌트일 뿐**: 2026-10-27 부터 규칙 대신 작은 결정 나무 묶음(`guess_model.json`, QuickDraw 낙서로 배움)이 추측하고, 확률 0.8 미만이면 「모르겠음」. QuickDraw 확인용에서 맞음 47% · 틀림 4% · 모르겠음 49% (예전 29% · 20% · 51%). 색칠한 아이 그림으로는 거의 안 재 봤다 → 여전히 사람이 고른다. 자세히: `eval_real/GUESS_IMPROVE.md`
- 날개 점 미리 놓기: 끝 = 그림 맨 왼쪽 · 맨 오른쪽, 뿌리 = 몸 축 양옆 날개 끝 거리의 18% 선에서 그림이 이어지는 위 · 아래 끝 (굵기로 재면 날개와 몸이 한 덩어리인 나비는 몸통이 너무 넓게 잡힌다). 옆모습 새는 미리 놓기가 맞지 않아 사람이 옮겨야 한다
- **실제 아이 그림은 아직 한 장도 안 돌렸다** — 그림이 우리가 만든 깔끔한 그림이라 의미 부여는 이르다. S-06 으로 넘어가는 비율(자동이 자신 없는 비율)도 실제 그림으로 재야 한다
- 사람(두 발) 카드는 안내만. 실제 서비스에서는 「자동이 자신 있으면 카드 없이 바로」가 기본이고 이 카드 화면은 자신 없을 때만 (팀 논의 필요)
- 여러 캐릭터(한 장에 여러 명, 여러 장)는 아직 생각만 — 지금은 가장 큰 덩어리 하나가 주인공
