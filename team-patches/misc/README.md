## 0-1 배포한 프론트가 서버 주소를 모른다 — `0001`

- **무엇을 왜**: 서버 주소가 `"/api/v1"` 고정이라, 프론트(Static Web Apps)와 백엔드(VM)가 따로인 배포에서는 서버를 못 찾는다. `VITE_API_BASE` 를 읽고, 비어 있으면 지금처럼 `/api/v1` 을 쓴다. 로그인(`auth.ts`)도 같은 값을 쓴다.
  - 이름은 백엔드 `deploy/README.md:17` 과 같다. 값은 **`/api/v1` 까지** 쓴다 (예: `https://api.example.com/api/v1`).
  - 표에 적힌 `??` 대신 `||` 를 썼다. `.env` 에 `VITE_API_BASE=` 처럼 빈 값이 있으면 `??` 는 빈 문자열을 그대로 써서 주소가 깨진다.
- **바꾼 파일**: `src/api/index.ts`, `src/api/auth.ts`, `src/vite-env.d.ts`, `.env.example`
- **확인한 것**: 값을 넣고 빌드하면 번들에 그 주소가 들어가고, 안 넣으면 `/api/v1` 이 들어간다. 그림 · 음성 · 영상 주소(`preview_url` 등)는 백엔드가 절대 주소로 주므로(`storage.url`) 따로 고칠 것이 없다.
- **남은 것**
  - 백엔드 `deploy/README.md` 는 「백엔드 주소로」라고만 적혀 있다. **`/api/v1` 까지 쓴다**고 한 줄 맞춰야 한다 (백엔드 쪽 일).
  - 배포 백엔드의 `CORS_ORIGINS` 에 Static Web Apps 주소를 넣어야 한다 (기본값은 `http://localhost:5173` 뿐).
  - 실제 배포로는 확인하지 못했다.
