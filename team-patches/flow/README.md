- 커밋마다 `npm ci` → `npm run typecheck` → `npm run build` 통과.

  dev 서버는 주소마다 같은 `index.html` 을 주므로 HTTP 응답만으로는 화면을 알 수 없어서 브라우저로 봤다.

  분석이 고른 오류 코드로 실패하게 했다 (저장소 코드는 바꾸지 않음).
- 「고치기 전에 문제가 있었다」는 1-1 · 8-6 은 패치를 뺀 상태로도 돌려서 문제가 보이는 것을 확인했다.

## 항목별

### 0001 · 1-1 새로고침 · 뒤로 가기로 들어오면 흰 화면

- **무엇을 왜**: 그리는 도중에 `nav()` 를 부르면 react-router 6.30.6 이 첫 그리기 중의 이동을 무시한다
  (`dist/index.js:225` `if (!activeRef.current) return;`). 그래서 빈 화면만 남았다.
  `return <Navigate to=… replace />` 로 바꿨다.
- **바꾼 파일**: `S05Confirm.tsx` · `S05Name.tsx` · `S06Joints.tsx` · `S09Story.tsx` · `S10Order.tsx` — 각각 import 한 줄 + 그 줄 하나.
- **요소**: 화면 단위 (S-05 · S-05N · S-06 · S-09 · S-10). 05 「7. 상태 처리 기준」 새로고침.
  커밋 제목의 「S-05 이름」은 05 의 S-05N 이다.
- **확인한 것**: 새로고침 상태로 `/confirm` `/name` `/joints` → `/upload`, `/story` `/order` → `/` 로 옮겨 가며 화면이 보인다.
  패치 전에는 다섯 곳 모두 주소만 남고 화면이 비었다.
- **겹침**: `S09Story.tsx` 는 import 줄과 `if (!story)` 줄 두 줄. 로컬 판에서 줄 위치가 달라도 이 두 줄만 손으로 옮기면 된다.
- **남은 것**: 05 는 「새로고침해도 같은 탭 안에서는 만들던 이야기가 남는다」인데, 지금 `store/session.ts` 는 메모리에만 있어서
  새로고침하면 처음 화면으로 돌아간다. 흰 화면은 없어졌지만 「남는다」까지는 아니다. session.ts 를 크게 건드려야 해서 넣지 않았다.

### 0002 · 4-1 사진 올리기를 끈 상태에서 E-01 「앨범에서 고르기」

- **무엇을 왜**: `UNSUPPORTED_IMAGE` 의 버튼이 늘 「앨범에서 고르기」였는데 앨범 버튼(S-03-05)은 사진 올리기를 켰을 때만 있다.
  꺼져 있으면(기본) 다른 그림 오류처럼 `DRAW_TEXT` 로 「다시 그려 볼까요?」 · 「다시 그리기」를 쓴다.
- **바꾼 파일**: `src/lib.ts` (`DRAW_TEXT` 에 한 줄 + 주석 한 줄)
- **요소**: E-01-03 · E-01-04, 근거 S-03-05
- **확인한 것**: 사진 올리기 꺼짐 + `UNSUPPORTED_IMAGE` → 「이 그림은 열 수 없어요 / 다시 그려 볼까요? / 다시 그리기」. 버튼은 S-03 으로 간다.
- **남은 것**: 05 E-01 표에는 「사진을 끈 경우」 문구가 따로 없다. 「다시 그려 볼까요?」는 내가 고른 말이다 → 05 E-01 표에 한 줄 더하기 (문서 B7).

### 0004 · 9-2 같은 그림 오류가 반복될 때의 처리

- **무엇을 왜**: 연속 실패를 세는 곳이 없어 같은 안내로 계속 돌려보냈다 (F-CHR-07 필수).
  - 새 파일 `src/store/retry.ts` 에 횟수를 둔다 (메모리만). `session.ts` 를 건드리지 않으려고 따로 뺐다.
  - `S04Analyzing.tsx` 가 분석 결과를 센다: 성공이면 0, 실패면 +1. `ENGINE_ERROR` · `CONTENT_BLOCKED` 는 세지 않는다.
  - `E01Error.tsx`: 2회 → 보조 안내 「화면에 그려 볼까요?」 + 버튼 「화면에 그리기」 → S-03D.
    3회부터 → 보조 안내 「옆에 있는 어른에게 도와 달라고 해 볼까요?」 + 버튼은 그대로 「화면에 그리기」 → S-03D.
  - 지원 수준 1 전용 규칙(1회에 S-03D)은 **넣지 않았다** (10/27 수준 2 고정 결정).
- **바꾼 파일**: `src/store/retry.ts`(새로) · `S04Analyzing.tsx` · `E01Error.tsx`
- **요소**: E-01-03 · E-01-04 (05 E-01 「반복해서 걸러질 때」, 06 4-3, 03 F-CHR-07)
- **확인한 것**: NO_CHARACTER(1회, 평소 문구) → LOW_CONFIDENCE(2회, S-03D 권함, 버튼 누르면 `/draw`) →
  ENGINE_TIMEOUT(3회, 어른 부르기) → ENGINE_ERROR(셈 밖, 평소 문구) → 성공(`/confirm`) → MULTIPLE_CHARACTERS(다시 1회, 평소 문구).
- **결정 필요**:
  1. **3회째 버튼.** 05 는 3회에 「옆에 있는 어른에게 도와 달라고 해 볼까요?」만 적고 버튼은 말하지 않는다.
     지금은 보조 안내만 바꾸고 버튼은 S-03D 를 유지했다. 「어른에게 도움 받기」(S-06 처럼) 같은 다른 버튼이 필요한지 정해야 한다.
  2. **2회째 문구 위치.** 05 표의 「화면에 그려 볼까요?」를 보조 안내로, 버튼 이름은 S-03-04 와 같은 「화면에 그리기」로 했다.
  3. **`ENGINE_TIMEOUT` 을 셀지.** 05 는 「ENGINE_ERROR · CONTENT_BLOCKED 는 넣지 않는다」만 적어서 문서대로 S-04 시간 초과는 셌다.
     시간 초과는 그림 문제가 아니라서 빼는 게 맞을 수도 있다 (S-08 의 시간 초과는 S-04 성공 뒤라 원래 셈이 0 이다).
- **남은 것**: 새로고침하면 셈이 0 으로 돌아간다. 이미 화면에 그린 그림(S-03D)이 두 번 걸러져도 다시 S-03D 를 권한다
  (05 는 S-03D 가 「요구사항을 어길 수 없는 경로」라고 본다). `ENGINE_ERROR` 화면에 「처음으로」 버튼이 둘 보이는 것은 이 패치 전부터 있던 일이다.

### 0005 · 9-3 E-01 NO_CHARACTER 보조 안내

  비휴머노이드를 대회에 넣지 않으므로(10/27) 설계 문구가 시연과 맞다. `ERROR_TEXT` · `DRAW_TEXT` 두 줄.
- **바꾼 파일**: `src/lib.ts`
- **요소**: E-01-03 (05 E-01 표, 06 4-3 「사람을 그려 주세요」라고 쓰지 않는다)
- **확인한 것**: 사진 꺼짐 + NO_CHARACTER → 「그림에서 친구를 못 찾았어요 / 지금은 두 발로 선 친구만 움직일 수 있어요 / 다시 그리기」.
- **남은 것**: 「무엇을 바꾸면 되는지 한 문장」(E-01-03 정의)과는 결이 조금 다르다 — 설계 문서 쪽 판단이라 그대로 따랐다.

### 0006 · 8-6 듣는 중 떠나면 「잘 못 들었어요」

- **무엇을 왜**: 듣는 중에 「카드 다시 고르기」 · 「다음」 · 「이름 없이 할래요」를 누르면 듣기를 끊는데,
  끊긴 인식의 `onend` 가 「소리 없음」 실패로 돌아와 다음 화면에서 안내를 읽었다.
  우리가 끊은 것이면(`ctrl.signal.aborted`) `catch` 에서 조용히 끝낸다. `voice.ts` 는 그대로다.
- **바꾼 파일**: `S07Steps.tsx` · `S05Name.tsx` — 각각 `catch` 첫 줄 하나.
- **요소**: S-07-08 (S-05N 말로 짓기도 같은 일)
- **확인한 것**: 크롬처럼 `abort()` 하면 `onerror(aborted)` → `onend` 를 부르는 가짜 음성 인식을 넣고 돌렸다.
  패치 전: 떠난 뒤 「잘 못 들었어요. 한 번 더 말해 볼까요?」를 읽음 (S-05N · S-07 둘 다). 패치 후: 읽지 않음.
- **겹침**: `S07Steps.tsx` 는 로컬 판에서 이 `catch` 가 바뀌었을 수 있다. 같은 한 줄을 `catch` 맨 앞에 넣으면 된다.
- **남은 것**: 실제 마이크로는 확인하지 못했다. 끊기 직전에 글자가 이미 들어온 드문 경우(`then` 쪽)는 그대로 둔다.
